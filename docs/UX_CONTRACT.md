# TIPLOOP UX 계약

> 기준 제품 사양: `docs/product-specs/tiploop-service-research.md`

## 정식 화면 구조

- 홈 `/`: 내 연구 노트 현황과 최근 기록
- 보관함 `/explore`: 내 기록 검색
- 적용 큐 `/explore?focus=applied`: `실제로 적용할 것`이 있는 기록
- 새 분석 `/posts/new/write?category=reference`: 서비스 분석 작성
- 상세 `/posts/{id}`: 본인 기록 읽기
- 수정 `/posts/{id}/edit`: 본인 기록 수정
- 계정 `/users/{id}`: 본인 계정과 기록

## 데이터 경계

- 홈·보관함·상세·수정·계정 화면은 로그인 사용자만 접근한다.
- 연구 노트 조회와 수정은 현재 사용자의 `author_id` 범위에서만 수행한다.
- 다른 사용자의 기록은 존재 여부와 내용을 노출하지 않는다.
- 인증된 사용자가 소유하지 않은 기록 URL을 열면 의도적으로 동일한 404 화면을 돌려 존재 여부를 숨긴다.
- 개인 연구 화면에서는 공개 URL 기반 미디어 업로드를 제공하지 않는다.

## 공통 동작

| 작업 | 트리거 | 진행 상태 | 성공 위치 | 오류 | 포커스 |
|------|--------|-----------|-----------|------|--------|
| 생성 | 연구 노트 저장 | 버튼 크기를 유지한 busy 상태 | 새 상세 | 폼 상단과 필드 아래 | 첫 오류 필드 |
| 수정 | 변경사항 저장 | 중복 제출 차단 | 같은 상세 | 폼 상단과 필드 아래 | 첫 오류 필드 |
| 검색 | 검색 제출 | 브라우저 기본 문서 이동 | 보관함 결과 | 보관함 내 안내 | 검색 입력 |
| 취소·뒤로 | 취소·뒤로 | 로컬 초안 400ms 지연 저장 | 홈·보관함 또는 원래 상세 | 수정 중이면 unload 경고 | 목적지 제목 |

## 폼과 접근성

- 제품 폼은 `novalidate`를 사용하고 한국어 인라인 오류를 제공한다.
- 모든 input·textarea는 실제 label과 연결한다.
- 긴 textarea는 `resize: none`, 충분한 기본 높이, 입력에 따른 자동 높이 조절을 사용한다.
- 새 작성과 각 편집 화면은 현재 사용자 ID까지 포함한 서로 다른 localStorage 키로 기기 내 초안을 저장·복구한다.
- 서버 저장이 성공한 상세 화면에서만 해당 localStorage 초안을 지운다.
- 저장 버튼은 제출 중 중복 활성화를 막고 `aria-busy`를 제공한다.
- 키보드 포커스는 명확한 `:focus-visible` 처리로 표시한다.
- 하단 내비게이션은 현재 화면에 `aria-current="page"`를 표시한다.

## 검색

- 검색어는 URL `q`에 유지한다.
- 적용 큐 검색은 URL `focus=applied`를 검색·초기화 동작 내내 유지한다.
- 값이 있을 때 앱 소유의 `검색어 지우기` 버튼을 제공한다.
- 빈 보관함과 검색 결과 없음은 서로 다른 다음 행동을 안내한다.

## 문서 제목

`{화면 또는 서비스명} · TIPLOOP` 형식을 사용한다. 오류 화면도 현재 상태를 설명하는 제목을 가진다.
