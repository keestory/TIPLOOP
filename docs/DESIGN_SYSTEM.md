# 디자인 시스템

> 이 문서는 미리 정의된 토큰 세트가 아닙니다.
> 프로젝트마다 다른 디자인 시스템을 정의하기 위한 **프레임워크**입니다.

## 원칙

### 디자인 시스템은 제품에서 출발한다

토큰이나 컴포넌트를 먼저 정의하지 마세요.
제품이 해결하는 문제, 사용자가 누구인지, 어떤 맥락에서 쓰는지를 먼저 파악하세요.
거기서 필요한 것만 정의합니다.

### 기성품을 경계한다

Tailwind 기본 팔레트, Material Design 기본 컴포넌트, 
Bootstrap 그리드를 그대로 가져다 쓰면 "어디서 본 것 같은" 결과물이 됩니다.
프레임워크는 도구로 쓰되, 값은 제품에 맞게 조정하세요.

### 적을수록 강하다

컬러 10개보다 3개가 낫습니다.
컴포넌트 20종보다 잘 만든 5종이 낫습니다.
필요할 때 추가하세요. 미리 만들지 마세요.

## 디자인 시스템 정의 시 포함할 항목

프로젝트를 시작할 때 아래 항목을 **제품에 맞게** 채우세요.

### 컬러
- 브랜드 컬러 1-2개 (제품 정체성)
- 기능 컬러: 성공/경고/위험 (각 1개씩이면 충분)
- 텍스트/배경: 2-3단계
- "이 컬러는 왜 이 값인가?"에 답할 수 있어야 함

### 타이포그래피
- 본문 크기 1개, 제목 크기 2-3단계
- 폰트는 제품 성격에 맞는 것으로 (기본값을 의심하세요)
- line-height는 콘텐츠 밀도에 따라

### 스페이싱
- 기본 단위 하나를 정하고 배수로 사용
- "4px 기반 8단계 시스템" 같은 교과서적 정의 대신,
  실제 화면에서 편한 간격을 찾으세요

### 컴포넌트
- 제품에 실제로 쓰이는 것만 정의
- 각 컴포넌트의 상태는 실제 시나리오에서 도출
- "있으면 좋겠다"는 만들지 않는다

## 피해야 할 패턴

| 패턴 | 왜 문제인가 |
|------|------------|
| Tailwind 기본 팔레트 그대로 사용 | 모든 AI 생성물과 똑같아 보임 |
| Primary/Secondary/Tertiary 버튼 3종 세트 | 실제로 3종이 필요한 화면은 드묾 |
| 12컬럼 그리드를 기본값으로 시작 | 대부분의 화면은 2-3컬럼이면 충분 |
| sm/md/lg/xl 모든 사이즈 변형 미리 정의 | 필요한 사이즈만 만들 것 |
| 둥근 모서리 + 연한 그림자 카드 | 2020년대 SaaS 클리셰 |
| 좌측 사이드바 + 상단 헤더 고정 레이아웃 | 제품 특성을 고려하지 않은 기본값 |
| 파랑 Primary + 빨강 Danger + 초록 Success | 신호등 팔레트 — 생각 없이 쓴 티가 남 |
| 모든 상태에 체크 아이콘(✓) / 경고 아이콘(⚠) | 범용 아이콘 남발 |

## 좋은 디자인 시스템의 특징

- 제품을 보면 "이 회사/이 제품"이라는 걸 알 수 있다
- 정의된 것이 적지만, 정의된 것은 이유가 명확하다
- 새 화면을 만들 때 기존 요소로 80% 이상 구성 가능하다
- 예외가 필요할 때 예외를 허용하는 유연성이 있다
