# UX 가이드라인

## 핵심 원칙

### 명확성 > 간결성
사용자가 다음에 무엇을 해야 하는지 항상 알 수 있어야 한다.
"확인" 대신 "변경사항 저장"처럼, 버튼이 하는 일을 그대로 쓴다.

### 상태의 가시성
시스템이 지금 뭘 하고 있는지 사용자가 알아야 한다.
로딩, 성공, 실패, 빈 상태 — 각각 어떻게 보여줄지 설계 시점에 결정한다.

### 사용자 통제감
되돌리기 가능한 액션에는 되돌리기를 제공한다.
위험한 행동에는 확인 단계를 둔다.
사용자가 시작하지 않은 자동 행동은 최소화한다.

### 에러 방지 > 에러 처리
잘못된 입력을 사후에 거부하는 것보다 사전에 방지하는 게 낫다.
불가능한 행동의 UI 요소는 비활성화한다.

## 한국어 마이크로카피

정중하지만 딱딱하지 않게. 에러 메시지는 사과보다 해결 방법 우선.

- 에러: "네트워크 연결을 확인하고 다시 시도해주세요" (원인 + 행동)
- 빈 상태: "아직 등록된 항목이 없습니다. 첫 항목을 추가해보세요" (상태 + 다음 행동)
- 파괴적 행동: "이 항목을 삭제하면 복구할 수 없습니다. 삭제할까요?" (결과 + 확인)

## 접근성

WCAG 2.1 AA 기준. 체크리스트가 아니라 설계 습관으로:

- 키보드만으로 모든 기능을 수행할 수 있는가?
- 색상에만 의존하는 정보 전달이 없는가?
- 폼 요소에 레이블이 연결되어 있는가?
- 동적으로 변하는 콘텐츠를 스크린 리더가 인지하는가?

## 피해야 할 UX 패턴

| 패턴 | 문제 |
|------|------|
| 성공 시 초록 토스트, 실패 시 빨강 토스트를 기계적으로 적용 | 맥락 없는 피드백. "무엇이 성공/실패했는지"가 더 중요 |
| 모든 페이지에 빵 부스러기(breadcrumb) 넣기 | 깊이가 2 이하면 불필요. 정보 계층을 먼저 단순화할 것 |
| 빈 상태에 일러스트 + "아직 데이터가 없어요" | 감성 이전에 "여기서 뭘 하면 되는지"를 알려줄 것 |
| 모달 위에 모달 | 복잡한 플로우의 신호. 플로우 자체를 재설계할 것 |
| 테이블에 모든 필드를 보여주고 가로 스크롤 | 사용자가 실제로 보는 필드 3-5개만 기본 노출 |
| 설정 페이지에 토글 20개 나열 | 기본값이 잘 동작하면 설정은 필요 없다 |
