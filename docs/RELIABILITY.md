# 안정성 및 운영

> ops 에이전트가 참조하는 운영 원칙

## 배포 원칙

### 모든 배포는 롤백 가능해야 한다
- 코드 롤백: 이전 버전으로 되돌릴 수 있는가?
- DB 마이그레이션: 역방향 마이그레이션이 있는가?
- 설정 변경: 이전 설정으로 복구할 수 있는가?
- 롤백 불가능한 변경은 별도 승인 필요

### 점진적 배포
- 위험도가 높은 변경은 canary 또는 feature flag로
- 전체 배포 전에 일부 사용자로 검증
- "괜찮은 것 같다"가 아니라 지표로 판단

### 배포 후 15분이 가장 중요하다
- 배포 직후 에러율, 응답 시간, 리소스 모니터링
- 이상 징후 시 즉시 롤백 — 원인 분석은 롤백 후

## 장애 대응

### 우선순위: 완화 > 원인 분석 > 근본 해결
1. 사용자 영향을 최소화 (롤백, 트래픽 전환, 기능 비활성화)
2. 원인 파악
3. 재발 방지책 수립
4. 포스트모템 작성

### 포스트모템 원칙
- 비난 없이 사실 중심으로
- "누가 실수했나"가 아니라 "시스템이 왜 이걸 허용했나"
- 재발 방지 액션 아이템은 구체적이고 추적 가능하게

## 관측 가능성

### 로그
- 구조화된 JSON 로그 (에이전트가 파싱 가능)
- 요청 ID로 트레이스 추적 가능
- 개인정보는 로깅하지 않음

### 메트릭 — RED 메서드
- **Rate**: 초당 요청 수
- **Errors**: 에러 비율
- **Duration**: 응답 시간 (p50, p95, p99)

### 알림
- 증상 기반으로 설정 (사용자가 겪는 것 기준)
- "CPU 80%"보다 "응답 시간 2초 초과"가 더 의미 있는 알림
- 알림이 울렸는데 행동할 게 없으면 그 알림은 삭제

## 에이전트 실행 안정성

### 재시도
- API 호출 실패: 지수 백오프로 최대 3회
- 에이전트 태스크 실패: 오류 분석 후 1회 재시도
- 전체 파이프라인 실패: 사람에게 에스컬레이션

### 타임아웃
- 단일 에이전트: 최대 10분 (--max-budget-usd로 비용 제한)
- 리뷰 루프 반복: 최대 3회
- 전체 워크플로: 최대 30분

### 비용 제어
- 에이전트별 --max-budget-usd 설정
- 일일 총 비용 모니터링
- 비용 이상 시 알림
