# 설계 원칙

## 에이전트 가독성 우선

코드와 문서는 에이전트가 읽고 추론할 수 있도록 최적화한다.

### 규칙
- 함수는 단일 책임, 명확한 입출력
- 파일당 최대 300줄 (린터로 강제)
- 경계에서 데이터 형태를 파싱 (Pydantic, Zod 등)
- 구조화된 로깅 사용 (JSON 형식)
- 매직 넘버/문자열 금지 → 상수 또는 설정으로

### 네이밍
- 파일: `snake_case.py`, `kebab-case.ts`
- 클래스: `PascalCase`
- 함수/변수: `snake_case` (Python), `camelCase` (TypeScript)
- 상수: `UPPER_SNAKE_CASE`

## 경계 파싱 원칙

외부 데이터가 시스템에 진입하는 모든 경계에서 스키마를 검증한다:
- API 응답 → Pydantic 모델로 파싱
- 사용자 입력 → 유효성 검사 후 처리
- 설정 파일 → 스키마로 검증

내부 코드 간에는 타입 시스템을 신뢰한다.

## 의존성 선택 기준

1. 에이전트가 소스를 읽고 이해할 수 있는가?
2. 학습 데이터에 충분한 예제가 있는가?
3. API가 안정적인가?
4. 자체 구현이 더 저렴한가?

## TIPLOOP 연구 작성 패턴

- 분석 깊이는 기존 카드·보더·형광 포인트 토큰을 쓰는 라디오 카드 3개로 선택한다.
- 직접 질문 선택은 접히는 질문 은행으로 제공하고, 선택된 질문만 순서대로 답변 영역에 노출한다.
- 이미지·영상 선택 영역은 점선 보더의 단일 업로드 존과 파일별 미리보기 목록을 사용한다.
- 선택·키보드 포커스·드래그 진입·업로드 중·오류 상태를 색상만이 아니라 보더와 텍스트로 함께 표현한다.
- 비공개 첨부는 잠금 아이콘을 흉내 내는 문자 대신 `비공개 첨부`라는 명시적 텍스트로 표시한다.
