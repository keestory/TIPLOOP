# 설계 문서: 리뷰 레벨 시스템

> 상태: confirmed
> 작성일: 2026-04-04

## 요약

리뷰를 5단계로 구분하여, 변경의 규모와 위험도에 따라 적절한 깊이의 검증을 수행한다.

## 5단계 리뷰 레벨

```
Level 5: 프로덕션 시뮬레이션    ← 사람이 자는 동안 6시간+ 실행
  ↑ 관측 가능성 기반 검증 (로그, 메트릭, 트레이스)
  ↑ 사용자 여정 재현 + 성능 기준 검증
Level 4: 런타임 검증            ← 앱을 실제로 구동하여 동작 확인
  ↑ worktree 격리 환경에서 앱 부팅
  ↑ DOM 스냅샷 / 스크린샷 비교
  ↑ API 엔드포인트 호출 및 응답 검증
Level 3: 다중 에이전트 리뷰     ← 전문 리뷰어 3명이 각자 검토
  ↑ 보안 전문 리뷰어
  ↑ 아키텍처 전문 리뷰어
  ↑ 도메인 전문 리뷰어
  ↑ 과반수 승인 필요
Level 2: 정적 검증 + AI 리뷰   ← 린터 + 테스트 + AI 판단
  ↑ 아키텍처/네이밍/구조 린터 실행
  ↑ 테스트 실행 및 커버리지 확인
  ↑ AI가 diff 기반으로 리뷰
Level 1: AI 단일 패스           ← 현재 수준
  ↑ AI가 코드를 읽고 피드백
  ↑ 휴리스틱 기반 승인/거절
```

## 레벨 선택 기준

| 조건 | 레벨 |
|------|------|
| 문서/설정 변경만 | Level 1 |
| 단일 파일 로직 변경 | Level 2 |
| 다중 파일/도메인 변경 | Level 3 |
| UI 변경 또는 API 변경 | Level 4 |
| 인프라/배포/보안 관련 | Level 5 |

## 에이전트 가독성 고려사항

- 각 리뷰 레벨의 결과는 구조화된 JSON으로 반환
- 다음 레벨로 에스컬레이션 판단은 이전 레벨의 결과를 기반으로
- 사람 에스컬레이션은 Level 3 이상에서 블로커 발견 시
