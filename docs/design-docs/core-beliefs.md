# 핵심 신념 (Core Beliefs)

> 에이전트 우선 운영의 기본 원칙

## 1. 리포지터리가 유일한 진실의 원천이다

에이전트는 리포지터리에 있는 것만 알 수 있다.
Slack 대화, Google Docs, 사람 머릿속의 지식은 에이전트에게 존재하지 않는다.
모든 의사결정, 컨텍스트, 규범은 리포지터리에 마크다운으로 인코딩해야 한다.

## 2. 컨텍스트는 희소 자원이다

거대한 지침 파일은 에이전트의 성능을 저하시킨다.
AGENTS.md는 목차(맵)이지 백과사전이 아니다.
점진적 공개: 작은 진입점 → 필요시 깊이 탐색.

## 3. 제약이 속도를 만든다

에이전트는 엄격한 경계와 예측 가능한 구조에서 가장 효과적이다.
아키텍처 규칙은 문서화가 아닌 코드(린터, 테스트)로 강제한다.
위반 시 에이전트 친화적 오류 메시지를 제공한다.

## 4. 문서화가 부족하면 코드로 승격한다

규칙이 문서에만 있으면 시간이 지나며 무시된다.
반복적으로 위반되는 규칙은 린터나 구조적 테스트로 승격한다.
린트 오류 메시지 자체가 수정 지침이 된다.

## 5. 가비지 컬렉션은 지속적이다

기술 부채는 고금리 대출이다.
매일 조금씩 갚는 것이 한꺼번에 갚는 것보다 낫다.
doc-gardening 에이전트가 주기적으로 드리프트를 감지하고 수정한다.

## 6. "지루한" 기술이 에이전트에게 최적이다

결합성, API 안정성, 학습 데이터 내 표현이 풍부한 기술을 선호한다.
외부 라이브러리의 불투명한 동작보다 자체 구현이 나을 수 있다.
에이전트가 검사, 검증, 수정할 수 있는 형태를 우선한다.

## 7. 사람은 조정하고, 에이전트가 수행한다

사람의 역할: 우선순위 결정, 수용 기준 정의, 결과 검증
에이전트의 역할: 코드 작성, 테스트, 리뷰, 문서화, 배포
에이전트가 어려움을 겪으면 → 도구/가드레일/문서 중 무엇이 부족한지 파악
